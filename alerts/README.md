# 탭을 닫아도 오는 알림 (서버측 감시)

`index.html` 은 브라우저 탭이 열려 있어야만 감시가 돈다. 여기 있는 것들은 그 한계를
없애기 위한 경로다 — GitHub Actions 가 10분마다 모비 API 를 찔러보고, 조건이 맞으면
카카오톡 "나에게 보내기"로 알린다. **컴퓨터를 꺼도 폰으로 온다.**

| 파일 | 역할 |
|---|---|
| `watch.py` | 감시·판정·전송 |
| `settings.json` | **직접 올려야 함** — 앱에서 내보낸 설정 파일 |
| `state.json` | 봇이 만든다. `alerts-state` 브랜치에만 존재(main 엔 없음) |
| `../.github/workflows/alerts.yml` | 10분마다 실행 |

---

## 켜는 순서

### 1. 시크릿 3개 등록

저장소 → **Settings → Secrets and variables → Actions → New repository secret**

| 이름 | 값 | 어디서 |
|---|---|---|
| `MOBI_API_KEY` | 모비라이프 API 키 | 앱 위쪽 "API 키" 칸에 넣던 그 값 |
| `KAKAO_REST_KEY` | Kakao REST API 키 | developers.kakao.com → 내 애플리케이션 → 앱 키 |
| `KAKAO_REFRESH_TOKEN` | 카카오 refresh 토큰 | 아래 2번 참고 |

### 2. 카카오 refresh 토큰 얻기

앱 화면에서 이미 카카오 로그인을 해뒀다면 브라우저에 저장돼 있다.
사이트를 연 뒤 개발자도구(F12) 콘솔에서:

```
localStorage.getItem('ggMarket.kakaoRefreshToken')
```

나온 따옴표 안의 값이 refresh 토큰이다. **이 값은 님 계정으로 카톡을 보낼 수 있으니
채팅·이슈·커밋 어디에도 붙여넣지 말 것** — 시크릿 입력창에만 넣는다.

### 3. 감시 설정 올리기

앱에서 **🛠 도구 모음 → ⚙️ 설정/백업 → 내보내기(JSON 저장)** 를 누르면
`mobi-market-settings-YYYY-MM-DD.json` 이 받아진다.
그 파일을 **`alerts/settings.json`** 이라는 이름으로 이 폴더에 올린다.

> 이 파일에는 감시할 아이템 이름·임계값·조용한 시간대만 들어 있고
> **API 키나 카카오 로그인 정보는 애초에 안 들어간다**(앱이 일부러 뺀다).
> 공개 저장소에 올라가도 괜찮은 이유가 그것이다.

### 4. 확인

Actions 탭 → "가격 알림 감시" → **Run workflow** 로 수동 실행.
로그가 `감시 N개 · ... KST` 로 시작하면 정상이다.

## 화면과 여기서 각각 무엇을 하나

**여기서 판정하는 것** — 최신 스냅샷 하나와 직전 값만으로 결정되는 것들:

- ⬇ 저가하락 / ⬆ 저가상승 (임계 % + 연속확인 횟수)
- 🆕 신규매물 / ⚠ 품귀 (임계 개수)
- 💰 목표가 도달 (여유폭 재무장 포함)
- 🎯 트레일링 (새 고점마다 재무장)
- 🌙 조용한 시간대, ⏳ 동일 아이템 재알림 간격

**여기서 판정하지 않는 것:**

- **종합 신호 스코어**(🟢 사기 좋음 / 🔴 팔기 좋음) 와 **TEMA 추세전환**.
  둘 다 시세이력 백분위·이동평균이 필요한데, 그걸 파이썬으로 옮기면
  **같은 숫자를 만드는 구현이 두 개**가 된다. 한쪽만 고치면 화면과 카톡이 서로 다른
  값을 말하게 되고, 그게 제일 찾기 어려운 종류의 버그다.
  스코어는 화면이 유일한 출처로 남긴다.

## 알아둘 것

- **예약 실행은 밀린다.** GitHub 예약의 최소 간격은 5분이고, 부하가 걸리면 늦어지거나
  슬롯이 통째로 건너뛰어진다. 10분 주기는 "대략 10~20분 안에 온다"로 생각하는 게 맞다.
  초 단위로 급한 판단에는 여전히 탭을 열어두는 쪽이 빠르다.
- **공개 저장소는 60일간 활동이 없으면 예약 실행이 자동으로 꺼진다.** 이 워크플로는
  상태 브랜치에 계속 커밋하므로 활동이 끊기지 않지만, 오래 안 오면 Actions 탭을 확인할 것.
- **카카오 refresh 토큰은 유효기간이 지나면 만료된다.** 카카오가 새 토큰을 발급하면
  로그에 `♻ 카카오가 새 refresh 토큰을 발급했습니다` 가 뜬다. 그때 시크릿을 갱신해야
  한다(액션이 시크릿을 스스로 못 바꾼다). 갱신 없이 두면 토큰 갱신 실패로 워크플로가
  빨간 X 가 되고 메일이 온다 — 그게 알림 장치가 죽었다는 신호다.
- **로그에 시크릿을 흘리지 않는다.** `watch.py` 는 응답 본문·헤더를 출력하지 않는다.
  공개 저장소는 Actions 로그도 공개이고, GitHub 의 자동 마스킹은 "글자 그대로 같을 때"만
  걸려서 인코딩되거나 잘린 형태는 안 가려지기 때문이다. 이 원칙을 깨는 디버그 출력을
  추가하지 말 것.
- **제3자 액션을 쓰지 않는다.** `actions/checkout`·`actions/setup-python` 만 쓴다.
  외부 액션은 나중에 털리면 시크릿을 넘겨받은 채로 돌기 때문이다.
