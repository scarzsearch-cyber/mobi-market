# 탭을 닫아도 오는 알림 (서버측 감시)

`index.html` 은 브라우저 탭이 열려 있어야만 감시가 돈다. 여기 있는 것들은 그 한계를
없애기 위한 경로다 — GitHub Actions 가 10분마다 모비 API 를 찔러보고, 조건이 맞으면
카카오톡 "나에게 보내기"로 알린다. **컴퓨터를 꺼도 폰으로 온다.**

| 파일 | 역할 |
|---|---|
| `watch.py` | 감시·판정·전송 |
| `settings.json` | 앱이 자동으로 올린다(토큰 없으면 직접 올림) — 감시 목록·임계값 |
| `state.json` | 봇이 만든다. `alerts-state` 브랜치에만 존재(main 엔 없음) |
| `learned.json` | 봇이 만든다. **이것만 main 에 올라간다** — 화면이 읽어야 하므로 |
| `../.github/workflows/alerts.yml` | 10분마다 실행 |

---

## 켜는 순서

### 1. 시크릿 등록 — 필수는 하나뿐

저장소 → **Settings → Secrets and variables → Actions → New repository secret**

| 이름 | 필수 | 값 |
|---|---|---|
| `MOBI_API_KEY` | ✅ | 모비라이프 API 키. **여러 개면 줄바꿈이나 쉼표로 다 넣으면 된다** (아래 참고) |
| `KAKAO_REST_KEY` | 선택 | developers.kakao.com → 내 애플리케이션 → 앱 키 |
| `KAKAO_REFRESH_TOKEN` | 선택 | 아래 2번 참고 |

**키가 여러 개라면 전부 넣어라.** 줄바꿈이나 쉼표로 구분하면 감시기가 라운드로빈으로
돌려 쓰고, 429(한도)가 나면 다음 키로 넘어간다. 401 이 난 키는 그 실행 동안 제외한다.

★ **화면에서 쓰는 키와는 다른 키를 주는 게 가장 좋다.** 같은 키를 화면과 서버가 같이 쓰면
분당 30회 한도를 나눠 쓰게 되어, 정작 사람이 보는 화면에서 429 가 뜬다. 키가 5개라면
예컨대 3개는 화면에, 2개는 여기에 주는 식으로 갈라두면 서로 경쟁하지 않는다.

**`MOBI_API_KEY` 하나만 넣으면 바로 돈다.** 알림은 이 저장소의 이슈에 댓글로 달리고,
GitHub 이 그걸 메일로 보내준다 — 추가 설정이 없다(`GITHUB_TOKEN` 은 워크플로가 이미 갖고 있다).

카카오 두 개를 더 넣으면 그쪽이 우선된다. 필수로 두지 않은 이유는 **카카오는 앱 등록과
로그인이 필요하고, refresh 토큰이 두 달마다 만료돼서 사람이 다시 갈아줘야 하기 때문**이다.
그 한 가지 때문에 알림을 아예 못 받는 상태로 두는 것보다, 자격증명이 더 필요 없는 통로를
기본으로 두는 쪽이 맞다.

### 2. (선택) 카카오 refresh 토큰 얻기

앱 화면에서 이미 카카오 로그인을 해뒀다면 브라우저에 저장돼 있다.
사이트를 연 뒤 개발자도구(F12) 콘솔에서:

```
localStorage.getItem('ggMarket.kakaoRefreshToken')
```

나온 따옴표 안의 값이 refresh 토큰이다. **이 값은 님 계정으로 카톡을 보낼 수 있으니
채팅·이슈·커밋 어디에도 붙여넣지 말 것** — 시크릿 입력창에만 넣는다.

### 3. 감시 설정 올리기 — 자동이 기본

앱의 **🛠 도구 모음 → ⚙️ 설정/백업 → 🤖 서버 감시 동기화** 칸에 GitHub 토큰을 넣어두면,
감시 목록이나 알림 조건을 바꿀 때마다 **화면이 알아서 `alerts/settings.json` 을 갱신한다.**
손으로 내보내고 커밋할 일이 없다. 그 칸에 지금 서버가 무엇을 보고 있는지도 같이 표시된다.

토큰은 **Fine-grained personal access token** 으로, **이 저장소 하나만** 대상으로 잡고
권한은 **Contents: Read and write** 하나만 준다. 그렇게 하면 혹시 새더라도 이 게임 저장소
말고는 아무것도 건드릴 수 없다 — 계정 전체 권한이 아니다. 만료일도 짧게 잡아두는 게 좋고,
언제든 GitHub 에서 한 번에 폐기할 수 있다.

**토큰 없이 쓰고 싶다면**: 앱의 **[📤 GitHub에 올리기]** 버튼을 누르면 편집기가 열리고
내용이 채워진다 — 초록색 Commit 만 누르면 된다 (클립보드에도 같이 담기므로, 비어 있으면
붙여넣기 후 Commit). 토큰 없이도 앱은 "서버 설정이 여기와 다르다"는 것을 알려준다.

**손으로 적어도 된다**: `kind_id` 는 없어도 되고 `name` 만 정확하면 감시기가 알아서 찾는다.
같은 이름이 둘 이상이면 임의로 고르지 않고 건너뛰면서 로그에 알려준다.

> 이 파일에는 감시할 아이템 이름·임계값·조용한 시간대만 들어 있고
> **API 키나 카카오 로그인 정보는 애초에 안 들어간다**(앱이 일부러 뺀다).
> 공개 저장소에 올라가도 괜찮은 이유가 그것이다.

### 4. 확인

Actions 탭 → "가격 알림 감시" → **Run workflow** 로 수동 실행.
로그가 `감시 N개 · ... KST` 로 시작하면 정상이다.

## 화면과 여기서 각각 무엇을 하나

**여기서 판정하는 것** — 화면과 같은 규약(index.html 의 bandPosPct / rebuyInfo):

- 🔴 천장근접 (최저가 ≥ 천장의 N%, 기본 90) · 🟢 저가 (≤ N%, 기본 60) · 🔁 되사기 (≤ 내 판매가의 85%)
- ⚠ 품귀 (수량 감소 개수·%) · ⬇ 저가하락 / ⬆ 저가상승 (직전 대비 % 변동 + 연속확인)
- 💰 목표가 (여유폭 재무장 포함) · 🌙 조용한 시간대 · ⏳ 재알림 간격

천장 = 3일 평균가 × 1.5 (소유자 실측 4건). 평균가는 서버가 **스스로 추정하고 스스로 보정**한다 —
천장 알림이 켜진 아이템(기본 켜짐)은 시세이력을 한 번 더 받아(요청 +1) 72h 거래량 가중 평균을 내고,
최근 12h 에 물량이 마른 채 최저가가 한 값에 3캔들 이상 붙어 있으면(plateau, 수량이 평소의 절반 이하)
그 값÷1.5 를 평균으로 채택하며 보정 계수를 `state.json` 에 학습한다. settings.json 에 사람이 넣은
계수와는 더 최근 것을 쓴다. 최근 6h `max(high)÷1.5` 하한을 항상 적용한다.
규약은 `index.html` 의 `effectiveAvg` 와 같고 `test_rules.py` [13][14] 가 같은 픽스처로 검증한다.
로그에 `평균 31.3 (자동) 천장 47` 처럼 출처가 찍힌다.

그렇게 배운 계수는 `learned.json` 으로 **main 에 발행**된다(내용이 실제로 바뀔 때만 커밋).
`state.json` 은 `alerts-state` 브랜치에 있어 Pages 가 서비스하지 않으므로, 이 파일이 없으면
**아무도 탭을 안 켜둔 사이에 지나간 품귀를 서버만 알게 되고 화면과 카톡이 서로 다른 천장을 말한다**
(브라우저는 plateau 창 12h 이 지나면 그 국면을 다시 잡을 수 없다). `index.html` 의
`pullAvgFromServer` 가 settings.json 과 이 파일을 같이 읽어 **더 최근 계수**를 쓴다.
시각 단위가 다르니 주의 — `state.json` 은 초, 화면과 `learned.json` 은 밀리초다(`test_rules.py` [16]).

## 알아둘 것

- **예약 실행은 밀린다.** GitHub 예약의 최소 간격은 5분이고, 부하가 걸리면 늦어지거나
  슬롯이 통째로 건너뛰어진다. 10분 주기는 "대략 10~20분 안에 온다"로 생각하는 게 맞다.
  초 단위로 급한 판단에는 여전히 탭을 열어두는 쪽이 빠르다.
- **공개 저장소는 60일간 활동이 없으면 예약 실행이 자동으로 꺼진다.** 이 워크플로는
  상태 브랜치에 계속 커밋하므로 활동이 끊기지 않지만, 오래 안 오면 Actions 탭을 확인할 것.
- **카카오 refresh 토큰은 유효기간이 지나면 만료된다.** 카카오가 새 토큰을 발급하면
  로그에 `♻ 카카오가 새 refresh 토큰을 발급했습니다` 가 뜬다. 그때 시크릿을 갱신해야
  한다(액션이 시크릿을 스스로 못 바꾼다). 갱신 없이 두면 토큰 갱신 실패로 워크플로가
  빨간 X 가 되고 메일이 온다 — 그게 알림 장치가 죽었다는 신호다.
- **로그에 시크릿을 흘리지 않는다.** `watch.py` 는 응답 본문·헤더를 출력하지 않는다.
  공개 저장소는 Actions 로그도 공개이고, GitHub 의 자동 마스킹은 "글자 그대로 같을 때"만
  걸려서 인코딩되거나 잘린 형태는 안 가려지기 때문이다. 이 원칙을 깨는 디버그 출력을
  추가하지 말 것.
- **제3자 액션을 쓰지 않는다.** `actions/checkout`·`actions/setup-python` 만 쓴다.
  외부 액션은 나중에 털리면 시크릿을 넘겨받은 채로 돌기 때문이다.
